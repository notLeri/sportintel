# ADR-003. Пороги кластеризации

- **Статус:** принято (предварительно, до разметки реальных данных)
- **Дата:** 2026-10-08
- **Затрагивает:** BE-T2.14, BE-T2.15, BE-T2.20, `app_settings.clustering`

## Контекст

Скоринг кандидата (BE-T2.14) сравнивается с порогами `t_high` (прикрепить) и `t_low` (ниже — новое событие; между ними — серая зона). По ADR-004 основной режим — **лексический** (без эмбеддингов):
`score = (w_lex·lex + w_entities·jaccard + w_competition·same_comp) / (w_lex + w_entities + w_competition)`,
где `lex` — `pg_trgm.similarity` заголовков. Исходные пороги 0.82 / 0.60 были рассчитаны на косинус эмбеддингов. Для лексического скора они слишком строгие: перефразы одного факта почти никогда не набирают 0.82.

## Данные и метод

- `evals/datasets/clustering_v1.jsonl` — **синтетический** набор: 51 заголовок, 23 факта, перефразы разных изданий и 5 трудных негативов (те же команды, другой факт в пределах 72 ч). Разметку сделал ассистент.
- Реплей `tests/evals/clustering.py` идёт в памяти, в порядке `discovered_at`, и использует **тот же** `clustering.score/decide`. Similarity повторяет семантику pg_trgm (unit-тест).
- Сетка: `w_lex ∈ {0.3, 0.5, 0.7, 1.0}`, `lex_min ∈ {0.2, 0.3}`, `t_high` от 0.40 до 0.90 с шагом 0.01, `t_low = t_high − 0.2`. Критерий — max B-cubed F1 при false merges ≤ 3 %.
- Устойчивость: тот же прогон с «деградированными» сущностями (игроки удалены, так как их нет в справочнике). Выбор сделан по худшему из двух F1.

## Решение (лексический режим)

| Параметр | Было | Стало |
|---|---|---|
| `w_lex` | 0.5 | 0.5 |
| `lex_min` | 0.3 | **0.2** |
| `t_high` | 0.82 | **0.58** |
| `t_low` | 0.60 | **0.38** |

Результат на clustering_v1: B-cubed F1 0.946 (P 0.90, R 1.00), false merges 1.2 %, доля серой зоны 6 %. Худший F1 с деградированными сущностями — 0.928. Со старыми порогами F1 был 0.706: статьи об одном факте дробились на отдельные события.

Значения записаны как дефолты схемы `Clustering` в `platform/settings_store.py`. `app_settings` хранит только переопределения, поэтому отдельная seed-миграция не нужна. Admin может менять пороги без деплоя (BE-T4.10).

## Последствия и риски

- Набор маленький и синтетический, поэтому цифры оптимистичны. Основной риск — **ложные склейки разных фактов об одном матче** (превью и итог). Остаточные склейки на наборе как раз такие. Компенсация: ручной split/move (BE-T4.3/T4.4) и связи `possible_duplicate`.
- **Режим эмбеддингов (фаза L)** использует другой масштаб скора. При включении `ai_routing.embeddings=on` пороги нужно перекалибровать (`--grid` на наборе с эмбеддингами). До этого ориентир — 0.82 / 0.60 (см. unit-тест).

## Когда пересмотреть

- Продукт разметил реальный набор (`scripts/export_clustering_dataset.py --from … --days 10`, колонка `gold_cluster`) — перезапустить `make evals` и обновить таблицу.
- На пилоте (INFRA-T5.10) доля ручных merge или split превышает 10 %.
